# Troubleshooting

What you will find here: known symptoms, their cause and the fix. Every row is based on the source code or on measured evidence; rows marked "not verified" could not be checked on a real system.

## Symptoms

| Symptom | Cause | Fix |
| --- | --- | --- |
| The status bar shows `not logged in` right after you logged in | The status refreshes on start, after a switch, on `/gentle:accounts current`, after every agent turn and every 60 seconds; a login made in another terminal is seen at the next refresh. | Run `/gentle:accounts current`. If it still says `not logged in`, check that the login command used the profile's Claude folder shown by `/gentle:accounts current`, or run `gentle-accounts login <profile>`. |
| The status bar shows no email and I want the full one | The email is hidden by default (`showEmail` is not `true` in `profiles/settings.json`). | Run `/gentle:accounts email show` (or `gentle-accounts email show`). Anyone who sees your screen can then read it; `/gentle:accounts email hide` hides it again. |
| `create` says `"<name>" is a reserved word (it is a subcommand)` | `menu`, `list`, `current`, `create`, `delete`, `login`, `rename`, `session`, `startup`, `email`, `usage`, `help` are subcommands of `/gentle:accounts`, so a profile with that name could not be switched to by name. | Pick another name. A profile that already has such a name keeps working from `/gentle:accounts menu` and the picker. |
| I changed the setting from the CLI and the open session still shows the old text | The open session reads the setting on its next status refresh: after an agent turn or every 60 seconds. | Wait for the refresh, or run `/gentle:accounts current`. |
| On macOS the `default` login looks logged out | `CLAUDE_CONFIG_DIR` was set to `~/.claude`; the keychain entry depends on that variable, so Claude Code no longer finds the login. | Do not set `CLAUDE_CONFIG_DIR=~/.claude` in your shell. Leave it unset for `default`; see [How it works](how-it-works.md). |
| Both `/profile` and `/gentle:accounts` exist | The old `gentle-profiles` package is still installed next to the new one. | Remove the `git:github.com/fcireza/gentle-profiles` line from `packages` in `settings.json` and restart. |
| `Cannot parse <path>: <reason>` | That `auth.json` (pi's live one or a profile's) is not valid JSON or is not a JSON object. The switch read every file first, so nothing was changed. | Fix the JSON in that file or restore it from a backup, then switch again. At session start the same error shows as `gentle-accounts: Cannot parse ...`. |
| A profile lost a provider's login, or has another account, after a `/login` in pi | On macOS and Linux the credentials file is a link to the current profile's own file, so a `/login` made directly in pi is saved in the CURRENT profile and replaces that provider's token there. | Log in again on the right profile: from the accounts menu (it switches to the profile first) or in a session started with `gentle-accounts <profile>`. |
| `Cannot adopt a live login while the credentials file is linked to a profile: a login made there is saved in the current profile.` | The menu refused to adopt a login found in the live credentials file: while it is linked, that login already is in the current profile. | Nothing to adopt; log the other account in from the accounts menu or with `gentle-accounts <profile>`. Detected Claude logins can still be adopted. |
| `Cannot delete the session profile "<name>". Set another one or clear it with "session last" first.` | New sessions start on that profile, so it cannot be deleted. | Run `/gentle:accounts session last` (or set another session profile), then delete it. |
| `Cannot rename profile "<name>": a session started with gentle-accounts is using it. Close it first.` | A launcher session (`gentle-accounts <name>`) is still running on that profile, and its credentials are saved back under the old name when it ends. | Close that session, then run the rename again. |
| After a rename, an open session shows `not logged in` or asks to log in again | That session was already running on the renamed profile, so its `CLAUDE_CONFIG_DIR` still points at the old, moved folder. | Switch to another profile and back in that session, or restart it. |
| After `x` the provider shows logged in again | A session started with `gentle-accounts <name>` is still running on that profile and saves its credentials back when it ends or switches. | Close that session, then log the provider out again. |
| The session did not start on the session profile | It was started with an explicit `gentle-accounts <name>`, which wins for that launch (`GENTLE_ACCOUNTS_LAUNCH_PROFILE` is set). | Start gentle-shell without a profile name to use the session profile. |
| `Session profile "<name>" does not exist; starting on the last used profile.` | The session profile was deleted outside `/gentle:accounts`. Nothing was changed. | Run `/gentle:accounts session <name>` with an existing profile, or `/gentle:accounts session last`. |
| Two open sessions end up on different accounts, or a session suddenly uses another account's Codex or Anthropic credentials | Sessions started without the launcher share the global profile and the single `auth.json`, so a switch in one changes what the others read. | Start each session with `gentle-accounts <profile>`: it gets a private agent home. See [How it works](how-it-works.md). |
| A session asks to log in again although the same account works in another session | OAuth refresh tokens rotate: the SAME account in two live sessions can invalidate the token one of them holds. | Log in again with `/login` and prefer a different account (profile) per session. |
| `This chat has no session file, so it cannot continue on another account. Open the project with "<name>" in a new tab with o: gentle-accounts <name>` | `u` moves the chat by continuing its session file in a private session home, and an ephemeral chat has none. | Open the project with that profile in a new tab with `o`, or start the chat again with a session file. |
| `Could not start gentle-accounts: <error>. Is it on your PATH?` or `gentle-accounts ended with code <n>; this window keeps its current account.` | `u` runs `gentle-accounts <profile> --session <this chat>` and it could not start, or it failed. The window stays open and nothing was changed. | Put `gentle-accounts` on the `PATH` of this terminal (see [Install](install.md)) and try again. |
| `gentle-accounts usage` shows the usage box status instead of starting my profile named `usage` | `usage` is a subcommand and a reserved name. A profile created earlier with that name is still listed. | Run `gentle-accounts rename usage <new>`. |
| `gentle-accounts manages the agent home; do not pass --home, --link or --isolated.` | The launcher builds the session home itself. | Run it without those flags. |
| `gentle-accounts: cannot read <path>: <message>` | The shared `settings.json` is not valid JSON; the launcher stops before creating anything. | Fix the JSON in that file. |
| `gentle-accounts: refusing to use <path>: <reason>` | The temporary base folder for session homes is a symlink, belongs to another user or is writable by group or others. | Remove or fix that folder (it only holds session homes), then launch again. |
| `gentle-accounts: argument "<arg>" contains characters that cmd.exe would interpret (& \| < > ^ " %); pass it another way.` | Windows only: the launcher runs `gentle-shell` through cmd.exe, which would interpret those characters in an argument. Nothing was created. | Remove those characters from the argument, or pass the value another way (for example a file or an environment variable). Arguments with spaces are quoted for you. |
| `Could not open a new terminal tab.` in the menu | No supported terminal was detected (Windows Terminal, tmux, Terminal.app, iTerm2, gnome-terminal, konsole, kitty, wezterm), or it failed to open the tab. | Run the command shown below the message in another terminal, or choose `In this terminal`. |
| `Could not log <provider> in: <reason>` | The provider's login failed or a prompt was cancelled; nothing was written. | Try again from its provider row; if it keeps failing, run pi's `/login` on the active profile. |
| `Wait for the current turn to finish before switching profiles.` | The agent is busy; switching is only allowed when it is idle. | Wait for the turn to end, then run the command again. |
| `gentle-accounts: command not found` (or the PowerShell equivalent) | Installing from git does not put the launcher on your `PATH`. | Add the alias or PowerShell function from [Installation](install.md), or run `node <clone>/bin/gentle-accounts.mjs` directly. |
| `gentle-accounts needs Node 22.18 or newer (found <version>).` | The launcher runs the TypeScript sources with Node's built-in type stripping. | Install Node 22.18 or newer and make sure `node` on `PATH` is that version. |
| `Cannot run gentle-shell: <error>` | `gentle-shell` is not on the `PATH` of the terminal where you ran `gentle-accounts <name>`. The global profile was not changed and the session home is removed. | Install Gentle Shell or add it to `PATH`. With plain pi, use `/gentle:accounts <name>` inside pi instead. On Windows the launcher goes through the shell, so the shell's own "not recognized" error may appear instead (not verified). |
| `Cannot run claude: <error>` | The `claude` CLI is not on `PATH`. | Install Claude Code and check `claude --version` in the same terminal. |
| On Windows the printed login command fails for an unusual path | The Windows command puts the folder in double quotes, `$env:CLAUDE_CONFIG_DIR="<dir>"`, without escaping; a path with `"` or `$` would need manual quoting (not verified on Windows). | Edit the quoting by hand, or use `gentle-accounts login <profile>`, which passes the variable without a shell command line. |
| On Windows `gentle-shell` or `claude` installed through npm is not found | npm installs `.cmd` shims on Windows. | The launcher already runs them through the shell for that reason. If it still fails, check that `where.exe gentle-shell` finds them (not verified on a real Windows machine; covered by the CI matrix only). |
| A Codex or Anthropic profile stopped working after you used the same login elsewhere | OAuth refresh tokens rotate; when another tool refreshes the same login, the token saved in the profile can go stale. | Switch to that profile and log in again with `/login`. |
| The status bar does not appear and `/gentle:accounts` is unknown | The extension is not loaded: the package is not in that agent dir's `settings.json`, or Gentle Shell or pi was not restarted. | Check the `packages` list in `settings.json` for `git:github.com/fcireza/gentle-accounts`, then restart. |
| The launcher shows different profiles than Gentle Shell or pi | The launcher reads `PI_CODING_AGENT_DIR`, then `GENTLE_SHELL_HOME`, then `~/.gentle-shell/agent`; plain pi uses `~/.pi/agent`. | Set `PI_CODING_AGENT_DIR` to the agent dir you use before running the launcher. |

## Still stuck

Open an issue at [github.com/fcireza/gentle-accounts/issues](https://github.com/fcireza/gentle-accounts/issues) with the exact message. Never paste tokens or the contents of `auth.json`.
